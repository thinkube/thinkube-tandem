= The defect ledger
:page-type: reference

Every point where the run CATCHES a defect appends one structured row to
the ledger: a containment violation, a unit whose checks never went green,
a gate that could not run (exit 126/127 — an infrastructure defect, not a
code verdict), a supervisor disclosure (by definition a contract gap), a
confession found by the honesty scan, a finding carried to the delivery.

The ledger is one file per month at the store's root —
`defects/<YYYY-MM>.jsonl` — shared by every space, with each row naming
the space it came from. It is not kept inside the space, so deleting a
space never deletes the record of what went wrong in it.

Run *Tandem: Show Defects* to render it as a table.

The rows are find-time facts: what surfaced the defect, and what it cost.
Reading them monthly is how the methodology learns. A row that recurs is a
process defect, not a code defect — and the fix belongs in the process,
not in one more check.

== The tool's own defects

A run catches defects in the work it supervises. It cannot catch a defect
in the machinery that runs it, so Tandem's own repairs — hundreds of them
over a month — left almost no trace in a ledger that recorded everything
else. The one population the methodology most needs to watch was the one
it could not see.

A repair to the tool is a commit, so the commit is where it is said. A
line in the message names what was wrong:

[source]
----
Defect: the platform's verdict was compared in one case, so a pipeline
that passed was read as a failure
----

Every deploy harvests the trailers it has not harvested yet, writes one
row per repair — `activity: tool development`, `trigger: self-repair`,
`type: machine` — and remembers the commit it stopped at, so nothing is
recorded twice. The row carries the commit's sha, so a monthly reading
can go back to the change itself.

Nothing is inferred. A commit that says nothing records nothing: a ledger
read for learning is worth less than nothing when it is full of guesses.
The completeness of this half therefore rests on the person or agent
writing the commit saying so.

`type: machine` now means what its name says. The machine's own failures
— a gate that could not grade, a watchdog halt, a crash, a window
reloaded mid-run — were typed by where they were caught rather than by
whose fault they were, which left the column reading 2 when the true
figure was around 100.
