= While it builds
:page-type: concept

_What the run page shows between your signature and the report, and why the machine works in that order._

.TL;DR
After *Build these N* the page *the run* shows one card per piece of work with a state word, and a header counting *N of M workers done · N of M judged on the running product*. You can watch, press *Stop*, or answer a card that *needs you*; otherwise the report arrives on its own when the run ends, with the work merged, deployed and judged on the running product.

== The decision

The machine building your thing is not trusted to grade its own work. That one decision fixes the order of everything you see on the run page.

  tests --> gate
  gate --> hand["handing it over<br/>merged and pushed"]
  hand --> live["taking it live<br/>the platform builds and deploys"]
  live --> product["on the running product<br/>one reviewer per promise,<br/>in a browser"]
  product --> report["the report"]
....

* *preparing the tree* comes first because a project that does not build before the run touched anything could never ship what the run delivers. The door proves the project's own build and finds its test commands.
* The *check* card and the *code* card for one promise are two workers that cannot see each other. The checks exist before the code, so the coder cannot write to the test, and the test cannot be bent to the code.
* Whether a piece is green is decided by an *audit* on the real state, not by the coder saying so. A piece that is not green goes back for a bounded repair with the evidence.
* *tests brought under* is a third worker that brings the project's existing tests under the new behaviour after the code lands, so nothing that used to pass is left broken.
* *The closing gate* runs every check again from a clean tree, reads the delivered files for deferrals a worker confessed to, and runs the project's own suite. Nothing merges past a red gate.
* *handing it over* merges and pushes, and *taking it live* waits for the platform to build and answer at the address. This is a development platform, so finished work is not held back for approval: what comes back to you is the thing running, to keep or take back out.
* *on the running product* is where promises about pages are judged: one reviewer per promise opens the product in a browser, does what each line describes, and saves a picture at the moment it decides.

== What it saves you

* *Nothing is claimed that was not proved.* A check that could not run is reported as unjudged, never as a pass. A reviewer that never answered leaves the line unjudged.
* *Nothing outside the work is touched.* A worker that writes outside the files it declared has those files reverted, and the run says so.
* *You are asked only about intent.* A worker's question goes to the machine first; only a choice among behaviours your sentences do not decide reaches you, as *needs you*, in your own words.
* *A red gate withholds, never hands over.* If a promise cannot be kept after every repair, or the product does not build, the run ends *withheld*: the work stays on its branch and the report names what failed.

== Where it shows up

*The cards.* Each card is titled with the promise it keeps and wears a state word: *ready* (waiting for what it needs), *running*, *needs you*, *passed*, *failed*, *never ran* (the run stopped or something it waited on failed; not a failure of its own). A card in the work being built now also carries the word *cut*. Click a card to read its log; the bands name the kinds of card: *check*, *code*, *tests brought under*, *on the running product*, *audit*, *door*, *delivery*, *live*.

*The header.* *N of M workers done · N of M judged on the running product*, then *finished* or *finished, with failures*.

*Stop.* *■ Stop* on the header aborts every live worker; the run drains and reports what it had. A run is a process of its own, so *Stop* reaches it from any window that has the space open.

*Cuts.* The row at the top lists every signed piece of work the space has run. Choose one and switch between *Report* and *Run and logs*: the cards, the log of every step, and the pictures the reviewers took stay readable after the run.

*The status bar.* While a space works: *<space>: N/M units*, with *— needs an answer* when a worker is waiting on you.

== Limits

* While a run is in flight, looking back at an earlier cut waits until it ends.
* Reviewers on the running product go one after another; a product they cannot sign in to leaves those lines unjudged, and nothing already proved is taken away.
* If the platform refuses to build the merged work, the run repairs what the platform's own words name and pushes again, twice, then hands the answer to you with *Ask Claude to fix it*, *Ask the platform again* and *Take it back out*.
