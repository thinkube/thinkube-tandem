= Thinkube Tandem
:page-type: concept

_An experimental intent-driven development methodology for working with Claude Code, still changing._

.TL;DR
Say to Claude Code: "Put these three lines in the box of the tasks space:"

[source,text]
----
Finished tasks stop crowding the ones I still have to do.
I can see how many tasks I have without counting cards.
Deleting a task asks me first.
----

Claude calls Tandem's `save_draft` and the lines appear in the box, one per line. From there every press is yours: *Read these 3*, *Keep these 3*, *Group into things to build*, *Build the first*, *Build these N*. What you have afterwards is the change merged into your project, deployed, judged on the running product, and a report that says what happened to each of your sentences.

== The decision

You ask for a car and you get a tricycle: something that satisfies the description and is not the thing. That is the problem Tandem exists for. Working on your own with an AI coder, code arrives fast, and every check can be green while the thing you asked for is not there. What goes wrong is not the code.

* Nobody checks that what was built is what you asked. The coder says "done", and you read the diff or you trust it.
* Nothing records what was promised. A week later, the reason a thing works the way it does is in a conversation that scrolled away.
* Every conversation starts from nothing. What you decided last time is not in front of the coder this time.

Tandem's decision is that your sentence is the record. You write what you want, in your own words, one line per thing. The machine reads those lines, shows you how it understood them, and derives everything else from them in front of you: which files change, what must become true, which checks will prove it. Your words are never edited by the machine.

[d2,alt="You write sentences, the machine reads them and proposes things to build, you pick one and sign, workers build it under checks, it is merged and judged on the running product, and you decide"]
....
direction: down
write: "You write sentences in the box"
read: "The machine reads them and proposes things to build"
pick: "You pick one; it works out promises and checks"
sign: "You sign"
build: "Workers build it on a branch;\nthe checks are written before the code"
live: "Merged, deployed, judged on the running product"
decide: "The report; you decide"
write -> read -> pick -> sign -> build -> live -> decide
decide -> write: "what the work noticed\nbecomes the next sentences" {style.stroke-dash: 4}
....

Two moments are yours and only yours. *Sign* freezes exactly what you saw into work to build; nothing is built before it. *Decide* on the delivery: go on, take it back out, or run it again; nothing stays without it. Between the two the machine works alone, and it is not trusted. The checks are written by a worker that never sees the code. Whether a check is green is decided by a separate judge, not by the coder's word. A worker that writes outside the files it declared has those files reverted. Everything that could not be delivered is written on the report.

== What it saves you

* *No tickets.* You write the sentence a person would say. The promises are derived in front of you, with the choices the machine made listed for you to replace.
* *No reading of diffs to know whether it worked.* The report carries its proofs: which checks ran, which passed, what a reviewer judged on the running product, and what only you can confirm.
* *No silent scope creep.* What a worker touches outside its declared files is reverted.
* *No merge you did not choose.* The work waits for your decision.
* *No undocumented change.* Every thing carries a documentation promise, judged by a reviewer like the others; xref:from-sentence-to-promise.adoc#_documentation_is_part_of_every_thing[Documentation is part of every thing].
* *No post-mortems.* Every defect a run catches is one row in a ledger that outlives the space. xref:defect-ledger.adoc[The defect ledger] is how the method learns.

== Limits

* Keeping, choosing, signing and accepting are yours; Tandem's tools refuse them to Claude Code by design.
* A run is a process of its own: closing or reloading the window that started it does not end it.
* Tandem is still changing; a page and the product can differ for a while after a release.
