= Projects and identity
:page-type: concept

.TL;DR
A thinking space belongs to a project, and a project is one repository, or one folder inside it. Tandem records the project once, when you press *Tandem: Activate Repository*, and finds it again from the repository's own remote and path. Move the repository, clone it on another machine, and its spaces are there.

== The decision

For your spaces to still be there tomorrow, Tandem has to look at a repository and know which project it is. That link is kept in the store, beside the spaces, and never in your repository: it is minted once when you activate the project, and it holds the project's id, its label, its product grouping, and enough to find the repository again.

A repository is matched back to its project from what it can always say about itself: its git remote and the path of the project inside it, empty for a whole repository or a folder such as `packages/web` for a part of one. The remote is compared by what it points at, not by how it is spelled: an SSH address and an HTTPS address of the same repository are one repository. A repository with no remote is matched by where it sits on disk and re-links itself if you move it.

== What it saves you

* *Nothing to write by hand.* You activate a repository once; the record is the machine's.
* *A rename costs nothing.* The label is yours to change; nothing is keyed by it, so the spaces stay put.
* *A restore comes back whole.* The store is the thing you back up, and it carries the identity too, so every space re-attaches to its repository on a new machine.

== Where it shows up

* *Tandem: Activate Repository* creates the project; activating the same repository twice is refused, so one project's history is never split in two.
* The status bar shows *Tandem: <product> / <repository>*; *Tandem: Switch Repository* changes it.
* A git worktree, a second checkout of a repository you already have, is not a project. Activating one is refused and points you at the repository it belongs to.
* `.tandem/` in your repository keeps only facts about the code itself: how the project is installed, prepared, tested and built, its conventions when it declares any, and your prompt overrides. Those belong with the source.

== Limits

* A project record left in the repository by an older version is moved into the store the first time the project is seen.
