= The store
:page-type: reference

.TL;DR
Everything Tandem records lives in a separate git repository, `~/thinkube-tandem-store` by default, never in your code. Restore the store on a new machine and every space, delivery and record comes back and re-attaches to the right repository.

== What is in it

  cards/<id>.yaml                 one project's identity, and how to find its repository
  spaces/<project-id>/            every thinking space of one project
    <space-name>/
      name.txt                    the space's name as you typed it
      <author>/
        runs/<work>.log           the run log, written as it happens
        runs/cut-<work>.json      the signed work and its run's record
        deliveries/<work>.json    the delivery and its proofs
        digests/<sentence>.md     the reading of the code made for one sentence
        graphs/                   the derived graph
        records/                  the space's history, snapshot by snapshot
    tep-counter-<author>.txt      the numbering of signed work, TEP-<author>-<n>
  products/<name>.yaml            a product grouping label
  defects/<YYYY-MM>.jsonl         the defect ledger
  headless/                       runs started from the command line

`<work>` is the number of a signed piece of work, `TEP-<author>-<n>`; it is the number the *Cuts* row shows.

== The defect ledger lives at the root

`defects/<YYYY-MM>.jsonl` sits at the store's root, not inside a space. Every space writes to the same monthly file and every row names the space it came from, so deleting a space never deletes the record of what went wrong in it. xref:defects.adoc[The defect ledger, reference] says what the rows mean.

== What guards it

* *Autosync.* The store commits and pushes itself whenever it has changed; the pushed remote is the backup. A stale git lock left by a dead process is cleared rather than failing every sync after it.
* *Secret scan.* Every write is scanned for secret-shaped content, tokens, keys, private key blocks; a hit refuses the write and names the pattern.
* *Your words, verbatim.* Your sentences are stored as typed and never edited by the machine.

== Good to know

The store is one git repository. A second machine writes to the same store through its own clone and the shared remote.
