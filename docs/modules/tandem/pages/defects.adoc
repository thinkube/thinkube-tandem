= The defect ledger, reference
:page-type: reference

.TL;DR
Every defect a run catches is one row in `defects/<YYYY-MM>.jsonl` at the store's root. A row is written the moment the defect is found and never edited. *Tandem: Show Defects* renders the month as a table with the fate of every row. xref:defect-ledger.adoc[The defect ledger] is what the rows mean and why they are kept.

== The file

One file per month at the store's root, shared by every space; each row names the space it came from. A row is appended at the moment a run catches something: a worker writing outside its declared files, a check that never went green, a check that could not run at all, a question the run had to answer for a worker, a deferral found in the delivered code, a finding carried to the report.

== A row

[cols="1,3",options="header"]
|===
| Field | Holds

| `ts`, `version`
| When the row was written, and the Tandem version that wrote it.

| `space`, `spec`, `run`, `slice`, `unit`
| Where it happened: the thinking space, the signed work (`TEP-<author>-<n>`), the run, the piece of work and the worker.

| `activity`, `trigger`, `type`, `stage`, `impact`
| The classification; the values are listed on xref:defect-ledger.adoc#_the_axes[The axes].

| `detail`
| The evidence, in the words of whatever caught it.

| `refs`
| Related identifiers: a commit, a check, a file.
|===

== The fate of a row

A row says what surfaced, not what became of it. When a run ends it writes how it ended, and how each piece of work ended, beside the ledger under the run's id. Reading a row's fate then follows from the rows themselves:

* an impact that says it was repaired, such as *the author repaired its own work* or *closed what no other actor could*, reads **healed**;
* an impact that says nobody could, such as *the closer could not finish it either*, reads **reached the person**;
* otherwise the ending of the piece of work it was found in answers, and where there is none, the run's own ending;
* a run whose ending was never written reads **not known**.

*Tandem: Show Defects* prints the fate beside every row and totals the month: *N found · N healed by the run · N reached the person · N not known*.

== The tool's own defects

A run cannot catch a defect in the machinery that runs it, so a repair to Tandem itself is recorded from the commit that made it. A line in the commit message names what was wrong:

[source]
----
Defect: the platform's verdict was compared in one case, so a pipeline
that passed was read as a failure
----

Every deploy, and every start of the extension, harvests the lines it has not harvested yet and writes one row per repair: `activity: tool development`, `trigger: self-repair`, `type: machine`, with the commit in `refs`. A commit that says nothing records nothing.

`type` is a closed set the code cannot stray from: `code`, `test`, `contract`, `gate`, `machine`, `infrastructure`, `environment`, `decision`. The machine's own failures, a check that could not be graded, a stall, a crash, a lock nobody released, are typed `machine` wherever they are caught.

== Limits

* `activity`, `trigger` and `impact` are free strings chosen by the site that caught the defect; a monthly reading counts spellings as well as kinds.
* Rows from runs that ended before endings were written read *not known*.
